## Петля — одна команда, а не пять правил

```bash
mobile-loop                      # сборка → установка → сценарии → снимок → след
mobile-loop --flow flows/вход.yaml   # один сценарий
mobile-loop --no-build           # без пересборки, по стоящему APK
```

Скрипт либо проходит целиком, либо называет шаг, на котором встал, и улику.
След пишется в `$LOG_DIR/mobile/последняя-петля.json` — по нему гейт коммита
проверяет, что петля вообще была.

Пустые `APP_DIR` / `BUILD_CMD` / `APP_PACKAGE` в `~/.config/harness-mobile.conf`
= честный отказ петли с адресом. Заполняются первой задачей приложения — это
часть её закрытия, а не отдельная работа.

## Что делает петля и чего она НЕ делает

Делает: поднимает эмулятор (идемпотентно), собирает, находит свежий APK
**поиском файла**, ставит на устройство, гоняет сценарии Maestro, снимает
скриншот и проверяет, что PNG не пустой.

НЕ делает: не смотрит на скриншот. Посмотреть — это открыть картинку и назвать,
что на ней: кнопка на месте, текст не обрезан, отступы не поехали, нет заглушек
вместо данных. Отчёт «петля зелёная» без просмотра снимка — это «тест зелёный»
вместо «работает», то есть нарушение И-4.

## Живой прогон находит то, чего тесты не видят

Тест проверяет функцию; путь проверяет только путь. Пройди путь целиком — от
нажатия до результата на экране, а на выгрузках — до файла на диске. Два
дефекта, которые прошли мимо зелёных тестов на соседнем проекте: кириллица в
заголовке HTTP (заголовки — latin-1, выгрузка падала пятисоткой) и ссылка на
скачивание без токена (переход по `<a href>` не несёт заголовок авторизации).
Оба видно только на живом пути.

## Реальные устройства: Firebase Test Lab

```bash
ftl-run путь/к/app.apk            # потолок берётся из FTL_TIMEOUT паспорта
```

`gcloud firebase test …` руками **не вызывать**: сторож отобьёт вызов без
`--timeout`. Причина в деньгах, не в стиле: бесплатная квота — 60 минут в сутки
на виртуальных устройствах и 30 на физических, дальше поминутно.

`ftl-run` забирает результаты локально и вынимает из видео кадры (`ffmpeg`) —
потому что mp4 посмотреть нельзя, а PNG можно. Смотреть хотя бы по одному кадру
с каждой модели: вырез экрана, системный шрифт и тёмная тема ломают вёрстку
там, где эмулятор молчал.

## Группировать падения по ПЕРВОЙ СТРОКЕ ошибки

Одиннадцать красных проверок три дня числились тремя разными поломками; причина
была одна — тестам негде было запуститься. Красный тест может означать «негде
запустить», а не «сломано»: сначала первая строка ошибки, потом диагноз.

## Порядок отчёта владельцу

1. Что сделано — одной строкой.
2. Что видно на экране — своими словами по снимку (не «скриншот приложен»).
3. Чем подтверждено — команда и число: `mobile-loop`, сколько сценариев, какие
   модели в Test Lab.
4. Что НЕ покрыто автоматикой и требует его глаз или его устройства.
5. Статус в `dev-map.yaml` — `test`, пока владелец не подтвердил; `done` ставит
   его проверка, не моя.

Снимки и кадры отправлять **вложением**: путь на сервере владелец не откроет.
