## 9а. Проверка безопасности

**Вход:** дифф задачи и наряд кода `.tasks/<id>/безопасность-код.json`, который
делает `python3 scripts/check-security.py --task <id>` (индекс git при этом
ПУСТ: код задачи уже в коммитах, иначе скрипт откажет «в индексе чужое»).
**Выход:** бумага `.tasks/<id>/безопасность.yaml`, написанная помощником-opus.
**Готово, когда:** гейт закрытия принял бумагу (печать, вызов скила, свежесть,
ответы). Задача без задетых классов бумаги не требует: шаг платит только
прогоном кода.

Шаг идёт после ревью кода и до мутаций. Задетые классы считает КОД, а не
модель: вход (injection), секреты, права (access), зависимости, контейнеры,
веб. Вопросы чек-листа — `harness/config/security-check-list.yaml`.

Порядок помощника:

1. Первым действием зови скил `security-check` (это машинная запись хука; без
   неё бумага не принимается).
2. Прочитай наряд: `touched` — задетые классы, `findings` — находки кода.
3. По КАЖДОМУ вопросу задетого класса дай ответ `ok` с местом
   `where: файл:строка` (файл из задачи, строка есть в индексе) либо находку в
   формате §9 (`reviewer_role: security`, `rule_ref`, `reproducer`).
4. По каждой находке кода из наряда — запись в `code_findings` с `rule`, `file`
   и вердиктом: подтверждена (тогда она же в `findings`) или ложная
   (`false_positive: <причина>`).
5. Не задетые классы — `touched: false` с причиной одной строкой.
6. Файл пишется инструментом Write, не командой Bash: хук печатает только
   запись инструментом помощника.

Формат бумаги (ключи английские — пишет и читает модель):

```yaml
code_fingerprint: <вывод check-security.py --fingerprint <id>>
checklist: security-check-list.yaml@<sha256 файла>
classes:
  injection: {touched: true, answers: [{id: inj-sql, verdict: ok, where: "api/x.py:41"}]}
  containers: {touched: false, why: "дифф не трогает Dockerfile/compose"}
code_findings: [{rule: shell-input, file: api/x.py, verdict: false_positive, false_positive: "команда — константа"}]
findings: []        # формат §9; закрытая несёт closed: <sha коммита этой задачи>
verdict: clean      # clean | has_findings
```

Что судит гейт на закрытии (каждая проверка — своя причина словами): изменения
прочитаны; бумага есть; файл запечатан помощником и не правлен после; печать
модели opus; вызов скила тем же помощником; отпечаток кода совпал; ответ на
каждый вопрос задетых классов и на каждую находку кода; места ответов внутри
задачи; нет critical/major без `closed`; прогонов не больше
`max_runs_per_task` (три) — иначе вопрос владельцу. Ложное срабатывание кода
гасится маркером `# не-уязвимость: <причина>` в той же строке; маркер без
причины сам становится находкой.

Роль `security` в ревью кода (§9) и этот шаг не дублируют друг друга: роль не
назначается, если у задачи есть `безопасность.yaml`. Нет бумаги (классы не
задеты, признак промахнулся) — правило «работа с правами доступа обязательно
получает security-ревьюера» действует как прежде.

## Ревью по ролям

`.tasks/<Task-ID>/review/{security,performance,readability,generalist}.yaml` +
`arbiter.yaml`, сводящий находки и выносящий вердикт. Артефакты коммитятся вместе с задачей.

Правила:

- **Роли назначаются по характеру задачи, минимально достаточным набором.** Правка вёрстки
  не нуждается в security-ревьюере; работа с правами доступа — нуждается обязательно.
  Исключение (M-8): если у задачи есть `.tasks/<id>/безопасность.yaml` — бумага шага
  «безопасность» ([05-ПАЙПЛАЙН.md] §9а), — роль `security` не назначается: её вопросы уже
  заданы по чек-листу и проверены гейтом. Нет бумаги — правило действует как прежде.
  Назначать «все роли ради полноты» — платить за находки, которых не будет.
- Требование к находке — **воспроизводимый сценарий отказа**; находка без сценария
  отбрасывается. Формат находки — [05-ПАЙПЛАЙН.md].
- **Предел — два круга ревью на задачу.** Не сошлось — вопрос владельцу, а не третий круг.
- **Порог по числовой оценке модели-судьи не ставить**: оценка одного и того же кода
  скачет между прогонами. Критерий выхода из цикла счётный — не осталось находок уровня
  critical/major.
