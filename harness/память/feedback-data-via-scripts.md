Записано: 08.08.2026, при сборке пакета (дисциплина из гайда владельца).

**когда:** собираюсь читать в контекст файл/лог/выгрузку больше пары экранов или «пройтись по всем файлам X»

**Почему:** не сжигать окно контекста на сырьё — деградация окна = ротация раньше времени (04-ПЕРЕДАЧА, session-warden).

Правило: сырьё обрабатывает код (python3/скрипт в scripts/ или разовый python3 - <<'PY'), в контекст возвращается вердикт: числа, топ-N строк, пути. Это то же главное правило проекта («всё, что можно кодом — кодом») в применении к собственному окну. Ниша подсмотрена у стороннего набора code-operations-skills (гайд владельца, до 08.08.2026): его не ставим — дисциплина одной строкой дешевле плагина.

**Как применять:** `wc -l`/`stat` до чтения; больше ~200 строк или бинарь → скрипт + вердикт; повторная обработка → скрипт остаётся в scripts/ (норма UNIFIED/13: повторяемое становится скриптом).

**пересмотр:** если появится класс задач, где сырьё в контексте реально нужно (ревью прозы?) — уточнить порог.
