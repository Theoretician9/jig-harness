# 00 — ВВОДНЫЕ: решения владельца и паспорт сервера

> Зафиксировано: 08.08.2026, в диалоге с владельцем (этап 0 плана работ №1).
> Статус: все обязательные вопросы закрыты; открытые позиции помечены
> «заполнить при установке» с указанием, какой шаг они блокируют.

## 1. Три обязательных вопроса владельцу

### 1.1. Где владелец читает результат

**Мессенджер (Telegram).** Следствия — обязательные, не рекомендательные:

* интерактивные подтверждения и всплывающие вопросы **выключаются полностью**
  (норма `UNIFIED/02`): агент никогда не ждёт ответа в терминале;
* нужен рабочий канал: Telegram-бот + фиксированный chat_id владельца;
* проверка канала — **факт доставки** (сообщение получено в клиенте), а не лог
  отправки (норма `UNIFIED/08`: прибор врёт чаще механизма);
* подтверждение получения задачи — ack ≤ 30 секунд; «анонсировал — продолжай».

### 1.2. Автономность агента

**Полуавтомат → автомат.** Дословное решение владельца (08.08.2026):

> «так как это будет первая сборка то полуавтомат, потом автомат, как только
> она будет проверена — на новых серверах сразу автомат»

Толкование для пакета:

* **на этом сервере** агент стартует в полуавтомате: опасные развилки
  (выкат в прод, ротация сессии, необратимые операции) — анонс в канал и
  подтверждение владельца; всё остальное — сам;
* переход в автомат — не по ощущению, а по проверке: чек-лист приёмки пройден,
  первая задача прогнана через весь цикл, первая ротация сессии доказана живым
  переходом (этапы 3–4 плана). Переход подтверждает владелец;
* пакет собирается так, чтобы **переключение полуавтомат/автомат было строкой
  конфига, а не переделкой**: пороги и режимы — данные, не код;
* на следующих серверах этот же пакет ставится сразу в автомат.

Права: широкие с первого дня (владелец не отвечает на разрешения оболочки —
они выключены), безопасность держат **гейты и сторожа**, не разрешения.

### 1.3. Инварианты проекта (нельзя нарушать никогда)

Четыре, подтверждены владельцем. Агент узнаёт их в первые 30 секунд сессии
(живут в CLAUDE.md, сторожатся кодом):

| # | инвариант | чем сторожится (носитель) |
|---|---|---|
| И-1 | **Не терять данные.** Необратимые операции над БД/файлами — только при свежем бэкапе; деструктивные команды по проду — только через сторожа | хук guard_bash (PreToolUse) + политика бэкапов `UNIFIED/10` |
| И-2 | **Не выкатывать мимо ворот.** Выкат только `deploy.sh` (гейты, тег, авто-откат); ручная последовательность команд запрещена | deploy_guard.py + запрет ручного выката в сторожах guard_bash |
| И-3 | **Секреты вне репо и вебрута.** Ключи и токены никогда не попадают в git и публичные каталоги | check-secrets.sh в pre-commit и перед выкатом |
| И-4 | **Честность отчёта.** «Сделано» — только после живой проверки; «тест зелёный» ≠ «работает» | живой смоук в пайплайне (`UNIFIED/05`) + правила отчёта `UNIFIED/02` |

| позиция | значение | статус |

| Ресурсы (CPU/RAM/диск) | — | **заполнить при установке**; блокирует только числа-потолки в `server_hygiene_check` и `disk-cleanup` (в экземплярах — переменные с дефолтами под VPS 2 CPU / 4 ГБ / 60 ГБ, при установке сверить) |

## 3. Полигон оркестрации

**Нет.** Сервер — рабочий агент на харнесе, не полигон
`ORCHESTRATION_LAYER_SPEC.md`. Файл `04-SPEC-ПОЛИГОН.md` пакета состоит из
указателя «полигон — не здесь» и ссылки на то, где полигон будет жить.

Что из «полигонного» всё равно делается (дешёвые точки крепления планов №2–3,
решение плана №1, раздел «Связь с модулем эволюции»):

* JSONL-журналы гейтов и вызовов скилов пишутся с первого дня;
* журнал дефектов и реестр механизмов заводятся пустыми;
* демон-коллектор сигналов и демон-ревизии входят в `demons/`.

## 4. Следствия для остальных файлов пакета

1. **01-SPEC-УСТАНОВКА**: установка на чистый Ubuntu VPS с нуля; Max-подписка
   (вход по аккаунту, без API-ключа в окружении); Telegram-канал с проверкой
   доставки; все интерактивные подтверждения Claude Code выключены.
2. **02-КАРТА-НОСИТЕЛЕЙ**: инварианты И-1…И-4 — первые строки карты; каждый
   получает носителя не ниже уровня «хук/гейт».
3. **03-ЗАДАНИЕ-АГЕНТУ**: режим — полуавтомат; первая задача — реальная
   маленькая задача нового проекта через весь цикл; условия перехода в
   автомат — из п. 1.2.
4. **04-SPEC-ПОЛИГОН**: одна страница-указатель.
5. Потолки гигиены — переменные с дефолтами; сверка чисел — пункт чек-листа
   приёмки, не причина ждать.
