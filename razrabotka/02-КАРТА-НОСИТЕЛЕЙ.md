# 02 — КАРТА НОСИТЕЛЕЙ: каждое правило харнеса → код

> Вход: `00-ВВОДНЫЕ.md`, главы `UNIFIED/01–13`, `UNIFIED/templates/`.
> Составлена: 08.08.2026, по всем главам UNIFIED (после вливания дополнения
> от 08.08). Исполнение главного правила проекта: **внимание модели — последний
> носитель, а не первый**.
>
> Лестница носителей (выбирается верхний из пригодных):
> **демон/cron** (работает без агента) → **хук/гейт** (оболочка исполняет сама,
> нарушение не проходит) → **скрипт** (агент вызывает, код решает) → **скил**
> (правило с наблюдаемым условием срабатывания) → **постоянный контекст**
> (CLAUDE.md/STATE.md — только вечное) → голое внимание = **не носитель**,
> правило на этом уровне записано в реестр долгов (§5) с датой.
>
> Два жёстких критерия карты: (1) ни одно правило не остаётся на голом
> внимании без записи в §5; (2) у каждого демона, хука и скрипта колонка
> «чем проверяется» содержит способ обнаружить его СМЕРТЬ — «работает» не
> ответ, молчание сторожа неотличимо от порядка (норма `UNIFIED/08`).

## §0. Инварианты владельца — первые строки карты

| правило | носитель | артефакт | чем проверяется, что носитель жив |
|---|---|---|---|
| И-1 Не терять данные: необратимое — только при свежем бэкапе | хук/гейт + демон | `guard_bash.py` (деструктивные команды по данным → отказ/подтверждение) + `demons/backup.sh` | тест сторожа (больной случай: `drop`/`rm -rf` по данным отменяется); heartbeat бэкапа + deadman-алерт по возрасту последнего дампа |
| И-2 Не выкатывать мимо ворот | хук/гейт | `guard_bash.py`: пуш/выкат сам спрашивает `deploy_guard.py`; ручная последовательность выката — в списке запретов | `test_guard_bash.py` (пара красный/зелёный на каждое правило); живой больной случай: выкат при «занято» отменён |
| И-3 Секреты вне репо и вебрута | хук/гейт | `check-secrets.sh` в pre-commit и в воротах выката | больной случай: файл `token = "test123"` в репо → красный; после удаления — зелёный |  <!-- не-секрет: это образец больного случая -->
| И-4 Честность отчёта: «сделано» только после живой проверки | гейт (статусный) | валидатор dev-map в pre-commit: `done` требует `tested_at` (подтверждение владельца) или `owner_testable: false` | `pre-commit-hook.sh --selftest-devmap`: красная/зелёная фикстуры |

## §2. Ротация сессий — отдельный обязательный механизм

Четыре части, ни одна не висит на внимании модели (улика владельца 08.08.2026:
повторные компакты сами забивают окно; **компакт — сигнал, а не норма; больше
одного подряд запрещено — дальше ротация**):

| часть | носитель | артефакт | проверка живости |
|---|---|---|---|
| датчик: заполнение окна + счёт компактов по транскрипту | демон | `session-warden.sh` (пороги — в конфиге, не в коде) | heartbeat + журнал замеров; больной случай: транскрипт с двумя компактами → команда ротации |
| точка сохранения: передача обновляется на каждом рубеже шага | хук + скрипт | `stop_reminder.sh` + `handover-check.sh` (возраст файла) | больной случай: протухшая передача при активности → напоминание |
| завершение: закончить атомарный шаг, финализировать передачу, закрыть сессию | демон → агент | анонс session-warden владельцу (semi); подтверждение из `confirmations.jsonl` читает АГЕНТ перед завершением | журнал ротаций: команда → подтверждение завершения |
| перезапуск под капотом + проверка приёма | демон | session-warden поднимает headless-сессию с CLAUDE.md+STATE.md+передачей; новая сессия обязана назвать текущую задачу и следующий шаг; расхождение — стоп и сигнал владельцу | доля бесшовных ротаций в журнале (метрика эволюции); первая ротация прогоняется принудительно (этап 4) |

## §3. Полная трассировка правил по главам

Ниже — все правила глав 01–13 с назначенными носителями. Строки с носителем
«ДОЛГ» продублированы в §5. Артефакты, отсутствующие в §1, — очередь
достройки: заводятся агентом по мере первых задач (продукт стартует с нуля,
гейты кода активируются при появлении кода) — помечены знаком °.

### Глава 01 — Принципы и правила

| правило | носитель | артефакт | чем проверяется |
|---|---|---|---|
| Перед задачей читать спеку, план, доки, память | скил | строка таблицы срабатываний | ревизия памяти считает срабатывания |
| Известная проблема → записанное решение, не повторная диагностика | скрипт + скил | `KNOWN-ISSUES.md` + скил разбора аварии | больной случай: записанная проблема находится поиском |
| Замер важнее рассуждения; источник истины; победивший источник в рантайме | скил | строки «собираюсь сказать „починено“», «третья правка без сдвига» | ревизия памяти: счётчик срабатываний |
| Новый прибор — на заведомо больном случае; пороги в переменных | гейт | CI-тест «прибор × больная фикстура»° | молчание прибора на больной фикстуре валит CI |
| Живой прогон обязателен; зелёные тесты не заменяют | гейт (статусный) | статусы dev-map + тест-гейт | задача без живого прогона не получает `done` |
| После изменения: пересборка → логи → живость → скрин → отчёт | скрипт | `deploy.sh` (порядок зашит) | больной случай: убитый сервис → «не жив» |
| Хирургические правки; дифф прослеживается к запросу | скил | строка «готовлю коммит → перечитать дифф на шум» | ревизия памяти |
