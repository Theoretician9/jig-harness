# ИНСТРУКЦИЯ ВЛАДЕЛЬЦУ: установка и повседневная работа

> Всё, что можно кодом, делает `USTANOVIT.sh`. Здесь — подробный маршрут:
> что делаете вы, что увидите на каждом шаге, как выглядит нормальная работа
> и куда смотреть, когда что-то не так. Обзор системы целиком — `README.md`;
> техническая спека каждого шага — `razrabotka/01-SPEC-УСТАНОВКА.md`.

## Что получится в итоге

На сервере круглосуточно живёт агент: вы пишете ему задачи в Telegram, он
отвечает «принял» за полминуты, работает по пайплайну (спека → тесты → код →
ревью → выкат), отчитывается командами и числами, а не словами. Опасное
(выкат, необратимое) не делает без вашего «подтверждаю». Каждое утро в 08:00
приходит сводка: живы ли все контуры и сколько токенов потрачено за сутки.

# Часть 1. Установка

## 1.0. Что подготовить (10 минут, до сервера)

**Сервер:** Ubuntu 22.04/24.04, доступ root или sudo по SSH. Подойдёт VPS от
2 CPU / 4 ГБ / 60 ГБ (потолки под другое железо сверяются на приёмке).

**SSH-клиент — нормальный, не браузерный.** Windows Terminal, PuTTY или
Terminal на Mac/Linux. Браузерные терминалы (Wetty и подобные) ломают длинные
строки при вставке — на шаге входа получите `OAuth error: Invalid code`.

**Telegram-бот:**

1. В Telegram найдите `@BotFather` (синяя галочка) → команда `/newbot`.
2. Отображаемое имя — любое; username — уникальный, кончается на `bot`.
3. BotFather пришлёт **токен** вида `123456789:AAH...` — сохраните целиком.
   Токен = пароль от бота, никому не показывайте.
4. Свой **chat_id**: напишите боту `@userinfobot` — ответит числом.

**Аккаунт Claude** с подпиской Pro/Max — вход по аккаунту, ключ API не нужен.

## 1.1. Скопировать пакет на сервер (2 минуты)

Из каталога, где лежат ОБА каталога — `STARTER-PACKAGE` и `UNIFIED` (они
должны приехать вместе: UNIFIED — нормативная база, агент читает её главы):

```bash
scp -r "STARTER-PACKAGE" "UNIFIED" root@ВАШ_СЕРВЕР:/root/starter/
```

## 1.2. Запустить установщик (~15 минут, из них ваших — 2)

```bash
ssh root@ВАШ_СЕРВЕР
cd /root/starter/STARTER-PACKAGE && sudo bash USTANOVIT.sh
```

Сначала можно посмотреть, что он сделает, ничего не исполняя:
`sudo bash USTANOVIT.sh --dry-run`.

**Установщик задаст 6 вопросов одним блоком в начале** — дальше работает без
остановок:

| № | вопрос | что отвечать |
|---|---|---|
| 1 | имя проекта (латиницей) | например `myproject` — войдёт в пути |
| 2 | каталог кода | Enter = `/opt/<имя>` |
| 3 | каталог секретов | Enter = `/etc/<имя>/secrets` |
| 4 | chat_id владельца | число от @userinfobot (п. 1.0) |
| 5 | токен бота | вставить; ввод скрыт, нигде не печатается |
| 6 | вариант канала | Enter = **Б (свой диспетчер — поддерживаемый)**. А — эксперимент, до приёмки не включать: установщик предупредит, что чек-лист будет красным |

Дальше установщик сам: пользователь `agent` и каталоги → пакеты → Claude Code
с фиксацией версии → systemd-юниты (агент в tmux + диспетчер канала) → секреты →
настройки и переменные качества → раскладка харнеса (включая доставку UNIFIED)
→ crontab всех 10 демонов **со сверкой против таблицы из спеки** → прогон
каждого демона в чистом окружении. Каждый шаг печатает проверку; упавший шаг —
стоп с именем шага и командой диагностики: чините по подсказке и запускаете
`sudo bash USTANOVIT.sh --resume` — выполненные шаги пропустятся.

В конце — сводка (что поставлено, что проверено, что упало) и блок
**«ОСТАЛОСЬ РУКАМИ»** с готовыми командами. Это три действия следующего пункта.

## 1.3. Три ручных действия (~10 минут)

Только то, что физически нельзя сделать кодом. Команды напечатаны в блоке
«ОСТАЛОСЬ РУКАМИ» уже с вашими реальными путями — копируйте оттуда.

### Сначала — два правила, чтобы ничего не потерять

**Где вы вводите команды.** Всё ниже — команды ВАШЕЙ оболочки (SSH), кроме
одного места, отмеченного «внутри Claude Code». В самого агента вы вводите
ровно один текст — первый промпт; дальше общение только через Telegram.

**Агент живёт в tmux-сессии, а не в вашем терминале.** systemd уже поднял
сессию с именем `agent` и держит её: она переживает закрытие терминала,
разрыв SSH и перезагрузку сервера. Отсюда единственное, что важно запомнить:

| что нажали | что произошло |
|---|---|
| `Ctrl+B`, отпустить, затем `D` | **отключились** от сессии — агент продолжает работать. Так и надо выходить |
| `Ctrl+C` дважды или `/exit` внутри Claude Code | **закрыли агента**. tmux-сессия останется, но работать в ней будет некому |
| закрыли окно терминала / оборвался SSH | ничего страшного: агент в tmux, он продолжает |

Если агент всё-таки выпал в оболочку, сторож `session-warden` заметит это в
течение ~15 минут, поднимет его сам и напишет вам в Telegram. Но проще не
ронять: выход — `Ctrl+B`, затем `D`.

### а) Вход Claude Code по аккаунту (один раз) — делайте СРАЗУ В СЕССИИ АГЕНТА

Подключитесь к той сессии, которую держит systemd, и войдите в аккаунт уже
внутри неё. Тогда одна и та же сессия и авторизуется, и остаётся работать —
второй раз запускать ничего не нужно.

```bash
sudo -u agent -H tmux attach -t agent          # вошли в сессию агента
claude --dangerously-skip-permissions          # ← ЭТО НАБИРАЕТСЯ ВНУТРИ tmux
```

Появится длинная ссылка → откройте её **в браузере на своём компьютере** (не на
сервере) → авторизуйтесь → браузер покажет код → вставьте код обратно.
Затем Claude Code спросит про доверие к каталогу — `Y`.

⚠ Подключайтесь **обычным SSH-клиентом**, не браузерным терминалом: браузерные
рвут длинную строку кода переносами, и вход падает с «OAuth error: Invalid code».

Флаг `--dangerously-skip-permissions` — тот же, которым сторож поднимает агента
после ротации (`AGENT_START_CMD` в `harness.conf`). Запускать `claude` без него
не надо: тогда после первой же ротации команда запуска изменится у вас под
руками.

**Вход сохраняется на диске** (`/home/${AGENT_USER}/.claude/`) — он переживает выход,
перезагрузку и всё остальное. Больше входить не придётся.

Дальше **не закрывайте** Claude Code. Отключитесь от сессии: `Ctrl+B`, затем
`D` — вы снова в своей оболочке, агент работает.

### б) Проверка канала в обе стороны — в ВАШЕЙ оболочке

Установщик уже отправил вам пробное сообщение от бота (если нет — команда
отправки есть в блоке). Ответьте боту в Telegram словом `дошло`, затем:

```bash
ls -t /var/log/harness/inbox/ | head -1     # появился файл входящего
cat "/var/log/harness/inbox/$(ls -t /var/log/harness/inbox/ | head -1)"
```

Должно напечатать «дошло» — канал не только пишет, но и слышит.

⚠ Ручной `getUpdates` не вызывайте никогда: диспетчер — единственный
потребитель, ручной вызов украдёт сообщение и остановит диспетчер на 5 минут.

Если вы всё ещё внутри Claude Code — сначала `Ctrl+B`, `D`, и только потом эти
команды. Внутри Claude Code они не сработают: там не оболочка, а чат с агентом.

### в) Первый промпт агенту — единственное, что вводится ВНУТРИ Claude Code

```bash
sudo -u agent -H tmux attach -t agent    # вернулись в сессию (claude уже там)
```

Промпт напечатан в блоке «ОСТАЛОСЬ РУКАМИ» дословно с вашими путями — вставьте
его в чат агента. Он говорит: прочитать ОПИСЬ и razrabotka/03-ЗАДАНИЕ-НОВОМУ-АГЕНТУ.md и выполнять по
порядку с отчётами в Telegram.

После вставки — `Ctrl+B`, затем `D`. **С этого момента терминал вам больше не
нужен**: всё остальное происходит в Telegram.

### Как убедиться, что агент действительно жив (в своей оболочке)

```bash
systemctl is-active harness-agent                     # active — сессия держится systemd
sudo -u agent -H tmux ls                              # есть строка «agent: 1 windows»
sudo -u agent -H tmux display-message -p -t agent '#{pane_current_command}'
```

Последняя команда должна напечатать `claude` или `node`. Если печатает `bash` —
агент выпал в оболочку: подключитесь и запустите его заново той же командой
(или подождите ~15 минут, сторож поднимет сам и напишет вам).

## 1.4. Агент донастраивается сам (~1–2 часа, вы читаете отчёты)

По 03-ЗАДАНИЮ агент: делает `git init` и первый коммит каркаса; прогоняет
каждую проверку **на заведомо больном случае** (подложенный «секрет» краснит
гейт, запрещённая команда отменяется сторожем, бэкап снимается и
восстанавливается на чистый каталог); сверяет потолки конфига с фактическим
железом. По каждому блоку — отчёт в Telegram: команда + вывод, не слова.
Вопросы он задаёт сообщением с нумерованными опциями — отвечайте цифрой.

## 1.5. Приёмка (полчаса вашего внимания + сутки наблюдения)

Идёте по `razrabotka/ЧЕК-ЛИСТ-ПРИЁМКИ.md`: агент прикладывает выводы команд, вы
подтверждаете пункты, помеченные «**: владелец**»:

* пробное сообщение реально пришло; ack приходит за полминуты;
* **утренняя сводка (08:00) приходит КАЖДЫЙ день, даже когда всё зелёное.**
  Это главное правило наблюдения: отсутствие утреннего сообщения = авария
  сторожа, идите в диагностику (часть 3). Молчание ≠ порядок;
* больной случай сторожа сторожей: агент закомментирует один демон — завтрашняя
  сводка обязана назвать его по имени;
* **первая ротация — принудительно.** В Telegram придёт анонс «пора ротация» →
  ответьте `подтверждаю` → агент заполнит передачу и штатно завершит сессию →
  надзиратель перезапустит его → новая сессия обязана БЕЗ подсказок написать
  вам, какая задача текущая и каков следующий шаг. Назвала — бесшовность
  доказана;
* первая маленькая настоящая задача — через весь цикл (п. 2.1).

# Часть 2. Повседневная работа

## 2.1. Ставить задачи

Просто пишете боту в Telegram обычным языком: «сделай X», «почини Y»,
«посмотри почему Z». Агент: ack ≤30 с → по глубине задачи заводит спеку/план
(маленькая правка идёт коротким путём, критичное — полным циклом) → работает →
отчёт: что сделано, чем доказано (команда + число), что **«ждёт твоей
проверки»**.

Статус «сделано» задача получает только после вашего подтверждения — это
гейт в коде: пока вы не проверили и не сказали «работает», в карте задач она
числится «ждёт проверки». Внутренние работы (гигиена, рефакторинг), которые
вам проверить нечем, в очередь вашего внимания не попадают.

## 2.2. Подтверждения (полуавтомат)

Перед выкатом, ротацией и необратимым агент присылает анонс и ждёт. Ответьте
одним словом: **`да` / `ок` / `подтверждаю`** (для ротации — «ротация ок»).
Согласие живёт 60 минут (порог в конфиге) — протухло, агент спросит заново.
Это тоже код, не вежливость: ворота выката физически закрыты без свежей
записи вашего согласия. Не ответили — действие не происходит, работа над
другим продолжается.

## 2.3. Что приходит само

* **Утренняя сводка (08:00):** живость всех 10 демонов поимённо, состояние
  юнита диспетчера, расход токенов за сутки (вход/выход/кэш, по моделям),
  срабатывания сторожа команд, если были. Зелёная сводка тоже приходит —
  её отсутствие означает аварию.
* **Анонсы ротаций** — когда окно контекста подходит к порогу.
* **Раз в месяц — ревизия памяти:** список сомнительных записей, по каждой
  готовое предложение (удалить / уточнить / оставить). Отвечаете списком:
  «1 да, 2 нет, 3 да».
* **Тревоги демонов:** «тесно на диске после уборки», «проверка гигиены
  сломана» и т.п. — каждая с указанием, что делать.

## 2.4. Расширения

Ничего ставить руками не нужно: у агента есть скил `установка-расширений` с
таблицей «условие → команды» (первая фронт-задача → браузер и дизайн-гайд;
первый запрос документа → офисные скилы; первая внешняя библиотека → Context7
и т.д.). Наступило условие — агент анонсирует, ставит, записывает цель и через
месяц перемеряет пользу по журналу.

## 2.4-а. Возможности: крупные наборы (например, мобильная разработка)

Есть наборы крупнее расширения — со своими инструментами, скилами, запретами и
уборкой. В комплекте один: **`мобильная-разработка`** (React Native + Expo,
Android прямо на сервере, iOS через облако EAS — Mac не нужен).

**Он не установлен изначально, и это сделано намеренно:** 20 ГБ диска и
полгигабайта памяти под эмулятор нужны только тогда, когда приложение реально
появилось. Пока набор не поставлен, его скилов не существует, его запретов
сторож не читает, его каталоги уборщик не трогает.

**Как он включается.** Обычно сам: вы даёте задачу вроде «сделай мобильное
приложение для заявок» — агент видит условие, ставит набор под капотом и
отчитывается, что поставил и почему. Можно и попросить прямо, словами в
Telegram: «поставь мобильную разработку».

Если хотите посмотреть своими глазами (по SSH):

```bash
sudo -u АГЕНТ bash /путь/к/проекту/scripts/vozmozhnost.sh список
sudo -u АГЕНТ bash /путь/к/проекту/scripts/vozmozhnost.sh требования мобильная-разработка
```

Вторая команда — замер до установки: хватает ли диска и памяти, есть ли у сервера
аппаратная виртуализация (`/dev/kvm`). У каждого «нет» будет написано, чем это
лечится. Если виртуализации у тарифа нет — набор всё равно поставится, только
проверка пойдёт не на локальном эмуляторе, а на реальных устройствах в облаке.

**Что придёт вам.** Сразу после установки — файл **вложением**
(`мобильная-разработка-РУКАМИ.md`): пошагово всё, что физически не может сделать
агент. Коротко оттуда:

| что | почему только вы | сколько времени |
|---|---|---|
| одна команда с `sudo` (пакеты и группа `kvm`) | пароль root у вас; агент готовит скрипт, вы запускаете | 3 минуты |
| Firebase Test Lab: проект, биллинг, сервисный ключ | браузер, карта, ваша учётная запись Google | ~30 минут, один раз |
| вход в Expo (`eas login`) | ваши логин и пароль, агент их не хранит | 5 минут |
| Apple Developer: регистрация, 99 USD в год, налоговые формы | верификация личности через устройство Apple | 1–2 дня ожидания |
| Google Play: регистрация, 25 USD, анкеты | проверка документов | 1–3 дня |
| **12 живых тестеров на 14 дней** (закрытый тест Google Play) | требуются настоящие люди с настоящими устройствами | 14 дней — начинайте собирать заранее |
| платежи, пуши, камера, биометрия, «ощущение от продукта» | только настоящее устройство и ваши глаза | по мере надобности |

**Всё, чего в этом файле нет, агент делает сам и вас не спрашивает.**

**Что он делает сам, каждый раз.** После любой правки экрана — не «тест
зелёный», а полная петля одной командой: собрать → поставить на эмулятор →
прогнать сценарии по экранам → снять скриншот → **посмотреть на него** и назвать
словами, что видно (кнопка на месте, текст не обрезан, отступы не поехали).
Коммит правки экрана без свежего прогона гейт не пропустит — это проверка, а не
обещание.

**Три вещи, которые сторож не даст сделать даже случайно:** прогон на реальных
устройствах без потолка расхода (бесплатная квота — 60 минут в сутки, дальше
поминутно с вашей карты), ручной запуск второго эмулятора (уносит сервер вместе
с сессией агента), выкладка в стор без вашего подтверждения (выложенное обратно
не отзывается).

**Приёмка набора** — свой чек-лист, агент проходит его и присылает результат.
Пока он не пройден, работа с приложением носит статус «ждёт твоей проверки», а
не «готово».

**Отключить:** попросить агента или `vozmozhnost.sh снять мобильная-разработка` —
скилы и запреты исчезнут. Установленные программы и SDK останутся на диске:
удалять то, что стоило времени и трафика, сессия сама не имеет права; список
команд для удаления — в конце чек-листа набора.

## 2.5. Перевод в полный автомат

Когда чек-лист закрыт и несколько задач прошли без ручных спасений — меняете
одну строку (только вы):

```bash
sudo sed -i 's/^AUTONOMY=.*/AUTONOMY="full"/' /etc/harness/install.conf
```

В full агент ротируется и действует сам; подтверждения остаются только там,
где вы их явно попросите. На следующих серверах этот же пакет ставится сразу
в full.

# Часть 3. Если что-то пошло не так

| симптом | что делать |
|---|---|
| установщик упал | в его выводе — имя шага и команда диагностики; починить → `sudo bash USTANOVIT.sh --resume` |
| бот молчит на сообщения | `systemctl status harness-dispatcher` → не active: `journalctl -u harness-dispatcher -n 30`; частая причина — лишний префикс или перенос строки в файле токена: файл должен содержать ТОЛЬКО токен одной строкой (проверить: `sudo cat` файла из TG_TOKEN_FILE в install.conf) |
| **я вышел из Claude Code — агент умер?** | сессия `agent` в tmux держится systemd и переживает закрытие терминала. Умирает агент только от `Ctrl+C`/`/exit` ВНУТРИ Claude Code. Проверить: `sudo -u agent -H tmux display-message -p -t agent '#{pane_current_command}'` — должно быть `claude` или `node`. Если `bash` — сторож поднимет сам за ~15 мин и напишет; вручную: `tmux attach -t agent`, затем `claude --dangerously-skip-permissions`, выйти `Ctrl+B D` |
| **пришло «Агент выпадал в оболочку»** | сторож поднял агента сам, ничего делать не нужно. Если это были вы — выходите `Ctrl+B`, затем `D`, а не `Ctrl+C` |
| нужно ввести команду, а я внутри Claude Code | `Ctrl+B`, затем `D` — вы в своей оболочке, агент работает; вернуться `tmux attach -t agent`. Команды оболочки внутри чата с агентом не выполняются |
| «принял» приходит, но агент не делает | агент жив? `sudo -u agent -H tmux attach -t agent` — посмотреть глазами (выйти: `Ctrl+B D`); session-warden пинает его сам при непустой очереди раз в 10 мин |
| сообщение «не дошло» от агента | `/var/log/harness/tg_failures.log` — там причина от Telegram API |
| **нет утренней сводки** | это авария сторожа: `systemctl status harness-agent`; `sudo crontab -l -u agent` (должно быть 10 строк демонов); `tail /var/log/harness/heartbeat-watch.log` |
| сводка: «демон X — МЁРТВ» | `tail /var/log/harness/X.log` — последняя ошибка; после починки метка оживёт следующим прогоном |
| сводка: «сторож команд падал N раз» | `tail /var/log/harness/guard_exceptions.log` — причины; сторож при своих ошибках пропускает команды (fail-open), поэтому разобраться стоит |
| агент завис после ротации | норма: надзиратель перезапускает сам в течение 10 мин; не поднялся — придёт сигнал «нужен запуск», тогда `tmux attach` → `claude` |
| выкат «занято», хотя ничего не идёт | `ls /var/log/harness/locks/` — протухший операционный лок; свежее согласие давали? (живёт 60 мин) |
| совсем всё лежит, бот мёртв | аварийный канал мимо харнеса: `sudo -u agent bash /opt/ПРОЕКТ/scripts/emergency-send.sh "текст"`; дальше по SSH раздел А чек-листа заново |
| непонятно, что за механизм сработал | `harness/ОПИСЬ.md` — каждый файл: что держит и чем проверяется |

**Полезные места на сервере:** конфиги — `/etc/harness/{install,harness}.conf`
(пороги — данные, правьте смело); логи всего — `/var/log/harness/`; входящие —
`.../inbox/`; журналы гейтов/скилов/токенов/ротаций — там же; метки жизни
демонов — `/var/lib/harness/heartbeat/`; код проекта — каталог из вопроса 2
установщика.
