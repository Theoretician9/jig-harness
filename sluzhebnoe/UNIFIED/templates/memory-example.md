# Шаблон файла памяти + стартовый набор

Каталог: `~/.claude/projects/<slug>/memory/`. Один факт = один файл. Индекс — `MEMORY.md`.

---

## Формат

```markdown
---
name: <короткий-слаг-через-дефис>
description: <одна строка — по ней решается релевантность при вспоминании>
metadata:
  type: user | feedback | project | reference
---

<Факт одним-двумя абзацами.>

**Почему:** <что случилось, из-за чего это записано. Без причины правило выглядит
произволом и его нарушают.>

**Как применять:** <конкретное действие в конкретной ситуации.>

Связано: [[другая-память]], [[ещё-одна]].
```

Строка в `MEMORY.md`:

```markdown
- [Заголовок](файл.md) — крючок, по которому понятно, стоит ли открывать
```

## Стартовый набор для нового проекта

Завести сразу, до первой задачи.

### `feedback-communication.md`

```markdown
---
name: feedback-communication
description: Владелец читает только <канал>; ack ≤30с, анонсировал — продолжай, интерактивные prompt-ы не использовать
metadata:
  type: feedback
---

Владелец **не видит терминал**. Единственный канал — <канал>, чат `<id>`.

**Почему:** всё, что написано «в терминал», для него не существует. Интерактивные
инструменты выбора рендерятся в терминале — он воспринимает их как молчание.

**Как применять:**
- Ack в течение ~30 секунд на каждое сообщение, до начала работы.
- Обещание («сделаю», «посмотрю») — середина хода, не конец: сразу продолжать работу.
- Вопросы — сообщением с пронумерованными опциями, «ответь цифрой».
- `AskUserQuestion` и подобные — не использовать вообще.
- Останавливаться и ждать только там, где нужно РЕШЕНИЕ владельца.
```

### `feedback-code-bar.md`

```markdown
---
name: feedback-code-bar
description: Планка кода — стиль Торвальдса + SOLID по духу
metadata:
  type: feedback
---

Убирать частные случаи, а не добавлять к ним `if`. Функция делает одно и умещается
в голове. Имена говорят, что это; комментарий объясняет ПОЧЕМУ, а не ЧТО. Никакой
защиты от воображаемых бед.

**Почему:** проект строится быстро и почти целиком агентом; без явной планки код
расползается — правки лепятся к тому, что есть, вместо изменения устройства.
Владелец читает результат, а не диффы, поэтому качество кода — на агенте.

**Как применять:** признаки, что планка не выдержана — шестой `if` под новый случай;
модуль, знающий и про базу, и про HTTP, и про вёрстку; слой «на будущее» без второго
потребителя. SOLID по духу: разделять ответственности, не плодить интерфейсы ради шаблона.
```

### `feedback-test-not-done.md`

```markdown
---
name: feedback-test-not-done
description: Завершённое агентом, но не проверенное владельцем — статус «ждёт теста», не «готово»
metadata:
  type: feedback
---

Работу, законченную агентом и не проверенную владельцем вживую, помечать `test` (90%),
а не `done` (100%).

**Почему:** живой тест — последние 10%, и делает их человек. Карта, показывающая 100%
там, где никто не проверял, перестаёт быть источником правды.

**Как применять:** статус в манифесте карты; формулировки в отчёте — «сделано, ждёт
твоей проверки», не «готово».
```

### `hazard-parallel-tests.md`

```markdown
---
name: hazard-parallel-tests
description: Нельзя гонять два прогона тестов одновременно — общая тестовая БД даёт десятки ложных падений
metadata:
  type: project
---

Все прогоны бьют в одну тестовую БД, conftest делает TRUNCATE перед каждым тестом.
Два параллельных прогона стирают фикстуры друг друга.

**Почему:** ~30–40 несвязанных падений по всему suite. Дважды дебажили исправный код.

**Как применять:** не диспатчить агентов с тестами параллельно с коммитом и друг с другом.
При странных массовых падениях — сначала `pgrep -x pytest`, потом код.
Долгосрочно: своя БД на прогон.
```

### `hazard-background-cli.md`

```markdown
---
name: hazard-background-cli
description: Фоновый запуск CLI поднимает плагин канала связи и обрывает живой сеанс — только --strict-mcp-config
metadata:
  type: feedback
---

Любой запуск `claude -p` из скрипта/крона/фона обязан идти с
`--mcp-config '{"mcpServers":{}}' --strict-mcp-config`.
`claude mcp list` не запускать НИКОГДА.

**Почему:** плагин канала связи допускает одного потребителя обновлений и убивает
«устаревшего держателя» — то есть живой рабочий сеанс. Связь с владельцем обрывается
и восстанавливается только с его стороны.

**Как применять:** состав MCP смотреть чтением конфигов, не health-check-командами.
После фонового запуска проверять, что процесс плагина не появился.
Если канал сорвался — писать напрямую через API отправки сообщений.
```
