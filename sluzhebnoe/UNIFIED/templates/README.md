# Шаблоны

Файлы под копирование в новый проект. Собраны из двух рабочих харнесов; в описи
источник помечен: **AIE** и **CF**. Часть файлов — рабочие, снятые с живых серверов:
логика переносится как есть, а проектные места заменены плейсхолдерами вида
`/opt/<проект>` или вынесены в настройки вверху файла — их нужно подставить под свой
стек. Комментарии с датами и уликами внутри скриптов сохранены намеренно: это
документация решений, объясняющая, ПОЧЕМУ каждая строка такая.

Два общих правила из практики:

> В shell-скриптах имена переменных — **только латиницей**: кириллица в bash даёт
> `command not found`, и шаг молча перестаёт работать.

> Каждый перенесённый сторож **прогоняется на заведомо больном случае** (сузь потолок,
> подложи сироту, подсунь разросшийся STATE.md) — прогон на здоровом сервере, где он
> «ничего не нашёл», не доказывает ничего. См. [08-ПРИБОРЫ-И-ЗАМЕРЫ.md].

## deploy.sh и deploy_guard.py — связка, не дубли

Это два РАЗНЫХ инструмента одного пайплайна выката (см. [09-ВЫКАТ.md]):

- `deploy_guard.py` — **ворота**: отвечает на вопрос «можно ли выкатывать ПРЯМО СЕЙЧАС».
  Три проверки: идут ли долгие задачи, идёт ли чужой деплой в CI, не в пути ли выкат
  (сравнение кода в контейнере с рабочим деревом). Код 0 — можно, 1 — занято.
- `deploy.sh` — **сам выкат**: гарантированный порядок сборка → миграции → health →
  снимок карты, плюс неблокирующие самопочинки (`devmap-selfheal.sh`,
  `fix-claude-mem-project.py`).

Порядок: `deploy_guard.py && deploy.sh`. Ворота спрашиваются и перед выкатом, и
**перед запуском долгой задачи** — окно опасности симметрично. Не сливать их в один
скрипт: ворота нужны и без выката, выкат «--силой» возможен и мимо ворот, назвав цену.
Отдельно предусмотри фоновую задачу, раз в час помечающую брошенные прогоны
неуспешными — иначе они висят «выполняется» вечно и врут владельцу.

## Порядок установки

Скрипты живут в `scripts/` репозитория — рядом с `docker-compose.yml`, не в отдельной
папке: пути внутри CF-скриптов берутся относительно самого файла (`__file__`), чтобы
те же проверки работали и в CI, где сервера нет. Запуск из чужого места даст «нет
файла docker-compose.yml» — это не поломка, а неверное место.

```bash
# правила
cp CLAUDE.md <repo>/CLAUDE.md

# гейты коммита
mkdir -p <repo>/.tasks/_config
cp pre-commit-hook.sh <repo>/.tasks/_config/
chmod +x <repo>/.tasks/_config/pre-commit-hook.sh
cd <repo> && ln -sf ../../.tasks/_config/pre-commit-hook.sh .git/hooks/pre-commit
echo ".tasks/*/" >> .gitignore        # артефакты задач не коммитим, _config — коммитим

# скрипты (AIE + CF в один каталог)
mkdir -p <repo>/scripts
cp deploy.sh deploy_guard.py check-secrets.sh devmap-selfheal.sh \
   check-context-hygiene.py fix-claude-mem-project.py \
   disk-cleanup.sh server_hygiene_check.py rasshifrovat_golos.py <repo>/scripts/
chmod +x <repo>/scripts/*.sh <repo>/scripts/*.py

# хуки проекта (версионируются вместе с репозиторием)
mkdir -p <repo>/scripts/hooks <repo>/.claude
cp hooks/guard_bash.py hooks/session_state.sh hooks/stop_reminder.sh \
   hooks/test_guard_bash.py <repo>/scripts/hooks/
chmod +x <repo>/scripts/hooks/*
cp hooks/project-settings.json <repo>/.claude/settings.json
python3 <repo>/scripts/hooks/test_guard_bash.py   # прогон сторожа: 15 проверок

# карта разработки
cp dev-map.yaml <repo>/<backend>/app/modules/dev_map/dev-map.yaml
```

Расписание и CI:

```bash
# ночная уборка диска — cron пользователя, состоящего в группе docker.
# ПЕРВЫЙ запуск — только руками и только с --dry-run:
scripts/disk-cleanup.sh --dry-run
# потом в cron (вывод в лог направляет cron, скрипт в файл сам не пишет):
# 30 3 * * * /opt/<проект>/scripts/disk-cleanup.sh >> /opt/<проект>/logs/disk-cleanup.log 2>&1

# гигиена сервера: в CI — только правила compose (диск машины сборки к делу не относится),
# ночью на сервере — целиком:
scripts/server_hygiene_check.py --только-compose   # шаг CI перед вливанием
# 0 4 * * * /opt/<проект>/scripts/server_hygiene_check.py >> /opt/<проект>/logs/hygiene.log 2>&1
```

После установки — обязательные прогоны на больном случае: сузь потолок одного сервиса
ниже его пика и убедись, что `server_hygiene_check.py` ругается; раздуй `STATE.md` за
потолок и убедись, что коммит не проходит.

Для `rasshifrovat_golos.py` обязательная часть — строка в таблице условий памяти
(«пришло голосовое → расшифровать», см. [03-ПАМЯТЬ.md]): без неё после перезапуска
сессии агент снова ответит «не умею».

## Предупреждения

- ⚠️ `devmap-selfheal.sh` содержит критичный запуск фонового агента с
  `--mcp-config '{"mcpServers":{}}' --strict-mcp-config`. **Не убирать эти флаги** —
  иначе фоновый запуск поднимет плагин канала связи и оборвёт живой сеанс с владельцем.
  См. [11-ЛОВУШКИ.md]; тот же запрет держит хук `hooks/guard_bash.py`.
- `deploy_guard.py` в поставляемом виде намеренно не работает: заполнители в блоке
  `НАСТРОЙКИ` нужно подставить, переносится не код, а три проверки.
- Неотключённый, но ненастроенный шаг обязан оставлять след: `disk-cleanup.sh` пишет
  «КАТАЛОГ НЕ ЗАДАН» и «ОПОВЕЩЕНИЕ НЕ НАСТРОЕНО» вместо молчания — сохраняй это
  свойство при адаптации.
- Скрипты ссылаются друг на друга по именам из этого каталога
  (`deploy.sh` → `devmap-selfheal.sh`, `fix-claude-mem-project.py`;
  `pre-commit-hook.sh` и `hooks/session_state.sh` → `check-context-hygiene.py`;
  `hooks/guard_bash.py` → `deploy.sh`). Переименовываешь — правь ссылки.
