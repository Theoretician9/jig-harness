Записано: 08.08.2026, при сборке пакета (правила выкуплены авариями доноров, UNIFIED/11).

**когда:** сторож отменил команду и тянет его обойти; собираюсь запускать
`claude`, `pytest`, `docker`, `rm -r`, `drop ...` из сессии, скрипта или фона.

**цель:** не повторять купленные аварии и не обходить защиту сгоряча.

**Источник истины — код сторожа** `харнес/hooks/guard_bash.py` (хук PreToolUse:
совпадение с известной бедой → отказ с причиной). Эта запись — не второй список,
а ПОЧЕМУ запреты существуют; при расхождении верить сторожу и его тестам
(`python3 -m pytest харнес/hooks/test_guard_bash.py`).

**Почему (по запретам сторожа):**
- `claude mcp ...` и `claude -p` без `--strict-mcp-config` — Telegram допускает
  одного потребителя getUpdates: второй держатель убивает живой сеанс, связь с
  владельцем обрывается и восстанавливается только с его стороны.
- `docker compose restart` — не пересобирает образ: правка «не доехала», проверка
  показывает старое поведение.
- `drop database` / `dropdb`, `rm -r` по каталогам данных/бэкапов/секретов — И-1:
  данные владельца из сессии не уничтожаются; восстановление только из бэкапа.
- `docker cp` внутрь живого контейнера — И-2: ручной выкат мимо `deploy.sh`,
  живёт до первой пересборки, дерево расходится с продом.
- `git push` / `deploy.sh` при «занято» от `deploy_guard.py` — выкат поверх идущей
  работы убивает её (и наоборот).
- второй одновременный `pytest` — общая тестовая БД, TRUNCATE в фикстурах:
  десятки ложных падений, дебаг исправного кода.

**Как применять:** отказ сторожа читать как данность, не как препятствие: выполнить
безопасную часть отдельно, охраняемое действие — правильным путём (deploy.sh,
согласование в канале) или не выполнять. Обход сторожа — только решением владельца.
Новая купленная авария → новое правило в сторож + пара красный/зелёный тест +
причина сюда. Ложный запрет чинится правкой сторожа, не его отключением.

**пересмотр:** вместе с правкой guard_bash.py — запись и код меняются одним коммитом.
