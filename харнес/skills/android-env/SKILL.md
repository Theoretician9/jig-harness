## Что это за окружение

Ставится возможностью `мобильная-разработка` (`харнес/возможности/`). Устройство:

| что | где | чем управляется |
|---|---|---|
| Android SDK | `$ANDROID_HOME` (`~/android`) | `sdkmanager`, версии — в `МАНИФЕСТ.conf` возможности |
| виртуальное устройство | `~/.android/avd/<AVD_NAME>.avd` | `avdmanager`, имя — `AVD_NAME` паспорта |
| эмулятор | tmux-сессия `emulator` | `emu-start` / `emu-stop` / `emu-status` |
| данные петли | `~/.config/harness-mobile.conf` | собирается из паспорта, `APP_*` — живые |
| сервисный лок | `$LOG_DIR/locks/services/emulator.lock` | ставит `emu-start`, снимает `emu-stop` |
| лог эмулятора | `$LOG_DIR/mobile/emulator.log` | пишет сам эмулятор |

Пороги (`EMULATOR_MEM_MB`, `GRADLE_MAX_MEM`, `FTL_TIMEOUT`) — ДАННЫЕ паспорта.
Менять их правкой `МАНИФЕСТ.conf` + переустановкой возможности, не правкой скриптов.

## Порядок разбора: сначала замер, потом починка

1. `emu-status` — он и есть первый прибор. Различает три разных беды, которые
   выглядят одинаково («не работает»): нет tmux-сессии · устройство есть, но ОС
   ещё грузится · устройство есть и загружено, а приложение не установлено.
2. `emu-logs 200` — последние строки по пакету приложения; без пакета покажет
   падения из общего потока. В контекст целиком logcat не читать.
3. `tail -n 40 $LOG_DIR/mobile/emulator.log` — почему не поднялся сам эмулятор.

## Известные беды и что именно их лечит

| симптом | причина | лечение |
|---|---|---|
| `emu-start` отказывает со словами про `/dev/kvm` | нет прав на устройство или нет вложенной виртуализации у VPS | `sudo usermod -aG kvm $(id -un)` и **перезайти в сессию** (смена группы применяется только после релогина); если `/dev/kvm` нет вовсе — локального эмулятора не будет, проверять через `ftl-run` |
| устройство «есть», а тесты падают пачкой | ОС не догрузилась: `adb devices` показывает устройство раньше, чем `sys.boot_completed=1` | не обходить: `emu-start` ждёт именно загрузки; в своих скриптах ждать того же свойства |
| `adb install` — «несовпадение подписи» | на устройстве стоит сборка от другого ключа | `adb uninstall <APP_PACKAGE>` и повторить установку |
| эмулятор стартует минутами | быстрый снапшот не сохранён — прошлое завершение было не штатным | гасить только `emu-stop` (он делает `adb emu kill`); `tmux kill-session` снапшот теряет |
| сервер начал свопить, load вырос | эмулятор + сборка съели память вместе | `emu-status` покажет фактические МБ; потолки — `EMULATOR_MEM_MB` и `GRADLE_MAX_MEM` в паспорте; демон `server-hygiene` эту беду видит и называет |
| `sdkmanager` «висит» | ждёт согласия с лицензией на входе, а сессия не интерактивна | только `yes | sdkmanager --licenses` (сторож отобьёт вариант без `yes`) |
| места на диске нет | SDK + образ системы + сборки ≈ 20 ГБ | `disk-cleanup` чистит в том числе каталоги из `уборка.list` возможности; `df -h $HOME` до и после |

## Поднять окружение с нуля на новом сервере

```bash
bash харнес/scripts/vozmozhnost.sh требования мобильная-разработка   # сначала замер
bash харнес/scripts/vozmozhnost.sh поставить  мобильная-разработка
```

Установщик идемпотентен: повторный прогон обновляет части и НЕ затирает живые
ключи `APP_*`. Что осталось владельцу (sudo-шаг, Firebase, Expo, Apple) —
`docs/возможности/мобильная-разработка-РУКАМИ.md`, отправлять **вложением**.

## Правило, которое здесь легко нарушить

Пропуск проверки обязан проверять ВЕЩЬ, а не имя пакета: «стоит ли драйвер»
и «доступна ли база» — разные утверждения, и первое молчит, когда нужно второе.
Здесь то же: не «установлен ли qemu», а `-r /dev/kvm && -w /dev/kvm`. И у
каждого пропуска обязан быть адрес — чем именно запускать пропущенное.
